# Public launch

This build targets a single-origin **Render Free web service plus an external free Neon Postgres database**. `render.yaml` has no paid disk. On every boot, the server restores accounts, sign-ins and runs from Postgres into temporary files; every successful change is written back to Postgres before the API responds. Render's temporary files are not authoritative. Vercel is not needed to host the app.

The source repository is `https://github.com/officialpk956-wq/Case_helper`. The Neon `production` branch is linked by the ignored `.neon/` directory and declared in `neon.ts`; `neon deploy` applies that policy and `neon env pull` writes the ignored `.env.local`. Push and verify source changes before Render deployment. Never commit `data/`, `out/`, `.env*`, or database credentials. Set `DATABASE_URL` in Render's environment settings from the Neon connection string and `CONTACT_EMAIL` to the public contact address. Render supplies its HTTPS URL through `RENDER_EXTERNAL_URL`; set `PUBLIC_ORIGIN` only when using a custom domain. Do not paste credentials into issues, chat, or source files.

Run `npm ci`, `npm run build`, and `npm test` before deployment. After deployment, check `/healthz` and `/login.html`; register a new test account, complete a retention and venture case, restart or redeploy the service, confirm the same sign-in and scores remain, confirm another account cannot read either run, then delete the test account. Check desktop and mobile browser layouts and the console. Keep a broad announcement on hold until these checks pass on the actual HTTPS URL.

Free-tier limitations: Render spins the app down after 15 minutes without requests and cold starts can take about a minute. Neon has its own free plan limits. There is no password recovery, so a forgotten password means creating a new account. The app holds at most 200 runs; an older run of the same account can be replaced when full. The database snapshot implementation is intended for one Render instance and modest beta traffic. Browser drafts and timers remain local to each device. No analytics or email is included.
